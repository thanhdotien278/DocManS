- (constraint) Retain the existing phase 1 modular-monolith stack, domain boundaries, backend-only business mutation, and state-machine operations.
- (decision) An account has exactly one active system role; PI, member, scientific secretary, reviewer, council member, and ethics reviewer are record-scoped relationships.
- (decision) Every protected decision evaluates authenticated actor, active system role, organization scope, record participation roles, assignment scope, valid delegation grants, workflow state, and conflict policy; missing context fails closed.
- (decision) Conflict and restriction rules override additive role or delegation permissions; no highest-role or union-of-roles shortcut may bypass a denial.
- (decision) Each domain owns its typed participation and assignment relations; researcher profiles provide shared identity and history but do not replace proposal, project, council, review, ethics, or task policy models.
- (decision) Record delegations are explicit persisted grants with grantor, delegate, target type and id, action set, validity interval, status, revocation, and audit history; grants cannot widen organization scope or override conflicts.
- (decision) Protected record and list responses expose backend-derived viewer relationships, allowed actions, blocked actions, stable denial codes, and plain-language reasons through a shared capability contract.
- (decision) One shared authorization policy service composes domain-owned relationship resolvers and conflict rules; controllers and frontend code do not recalculate permission.
- (decision) The personal work hub is a scope-aware cross-module read model whose entries are independently authorized and whose action queue removes conflicting records while preserving an explanation.
- (decision) Researcher profile account linkage and minimum participation identity foundations must precede council and ethics conflict-sensitive implementation.
- (decision) Cross-module reminder, search, dashboard, report, personal-hub, and file integrations are added only after the source domain can provide authorized query or association contracts.
- (decision) The architecture is an adopted target contract, not a statement of current implementation; the foundation migration must retire legacy global business roles and multi-role authorization shapes before dependent work.
- (decision) Authorization dimensions return typed resolved-value, resolved-empty, not-applicable, or unresolved states; only unresolved or ambiguous applicable context fails closed.
- (decision) Denial reasons use one versioned registry and deterministic primary-code order: unauthenticated, organization scope, inactive relationship, workflow state, conflict, invalid delegation, then action not granted.
- (decision) Relationship and delegation intervals use server database UTC time with half-open bounds; lifecycle history is immutable, revocation wins immediately, and overlapping active same-type relations are rejected unless the domain explicitly allows multiplicity.
- (decision) Delegations use exact-match versioned action identifiers, forbid wildcards and chains, require initiation by the current action holder plus staff approval, and are revalidated authoritatively in the target mutation transaction.
- (decision) Capability, personal-work, and audit contracts are versioned shared contracts with minimum disclosure; proposal participants do not receive internal reviewer identity, score, comment, or consolidation data before the configured disclosure state.
- (decision) Source domains remain authoritative; researcher history and personal work are authorized query-on-read projections in phase 1, never mutation authorization sources, and partial source failure fails closed without counting inaccessible items.
- (decision) Protected mutations bind authorization to the same transaction or validated context versions; background jobs use a service principal plus captured initiator identity and re-authorize current source context before acting.
- (decision) Existing authorization seams must be migrated or consolidated into the shared policy contract; creating a parallel permission system is forbidden.
- (decision) AUTHORIZATION-CONTRACTS.md is the normative V1 companion for request-wide time, denial codes, relationship types, exact actions, delegation, capability, disclosure, personal work, jobs, audit, context versions, and integration fixtures.
- (event) Architecture spine contract companion added after deterministic lint, rubric/reality pass, and adversarial re-review.
- (event) Architecture spine finalized after all three reviewer gates passed with no remaining build-safety blocker.
